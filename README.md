## Why ChatAutopsy

- **🔒 Zero cloud.** Parsing, statistics, search and AI all run locally. No external APIs, no telemetry. Uploaded
  exports stay in memory; only a SQLite database is written to disk, and you can securely wipe it.
- **⚡ Fully automatic.** One command or one drag-and-drop: parsing, database, full-text index, scores, semantic
  search. Even the AI model is picked, downloaded and started from a panel.
- **📊 Everything is measurable.** More than 50 indicators, each with every person's value, who leads, by how much,
  and a *How to read this* box. A **report card** sums it all up in a 0-100 reciprocity index.
- **🧠 AI that quotes its evidence.** The AI Detective answers by querying SQL, hybrid search and a statistical dossier,
  and anchors every claim to real messages with date and time.
- **🏋️ Real-world scale.** Tested on a 1.3-million-message chat spanning 8 years.
- **🌐 English and Italian.** Bilingual interface (🌐 selector in the sidebar) and curated vocabularies in both languages
  (affection, conflict, apologies, blame, gaslighting…); the chat language is detected automatically.

## Quick start

```bash
git clone https://github.com/giuseppegambino92/ChatAutopsy.git
cd ChatAutopsy
./start.sh analyze ~/Downloads/ChatExport_2024-06-28     # builds everything and opens the dashboard
```

| You want to… | Command |
|---|---|
| just open the dashboard (and drop the file there) | `./start.sh` |
| try the made-up chat | `./start.sh demo` |
| also prepare the AI model during the analysis | `./start.sh analyze PATH --llm` |
| statistics only, as fast as possible | `./start.sh analyze PATH --embeddings none` |
| force the interface language | `./start.sh --lang en` (or `it`) |

On macOS you can also **double-click `ChatAutopsy.command`**.

The first run creates the environment in `.venv` and installs the dependencies (a few minutes, once); after that it
starts immediately. `start.sh` finds a Python ≥ 3.10 by itself (including Homebrew's) and offers to install one if missing.


When installed with `pip install chatautopsy` (outside the repository), data goes to `~/.chatautopsy`.
</details>

## How to export a chat

| App | How | What to give ChatAutopsy |
|---|---|---|
| **WhatsApp** (iPhone/Android) | chat → contact/group name → *Export chat* → **Without media** | the `.zip`, the unzipped folder or the `_chat.txt` file |
| **Telegram Desktop** | chat → ⋮ → *Export chat history* → **HTML** or **JSON**, no photos | the `ChatExport_…` folder (or its `.zip`) |
| **Telegram, whole account** | Settings → Advanced → *Export Telegram data* → JSON | `result.json` + `--chat "Chat name"` (default: the largest) |

Formats are detected automatically: WhatsApp iOS and Android, 12h/24h and every regional date order, multi-line
messages, omitted media (*image omitted*, `<Media omitted>`, Italian variants…), system messages filtered out;
Telegram JSON (single chat or full export) and HTML (multiple pages, dates in English/Italian/French/German/Spanish/
Portuguese, replies, stickers, forwards). **Forwarded** messages are recognised and excluded from the linguistic
metrics: a forwarded article is not "your" language.

## Every metric, explained

<details>
<summary><b>Investment and initiative</b></summary>

| Metric | Definition |
|---|---|
| Message / character share | % of the total written by each person; characters weigh effort better than messages |
| Mean length and distribution | characters per text message written by the sender (mean, median, percentiles, bands 1-5 … >350) |
| Questions per 100 messages | question marks per 100 text messages |
| Opening conversations | who writes the first message after ≥ 6 hours of silence |
| Closing conversations | who sends the last message before a pause > 6 hours |
| Chasing | chains of ≥ 2 (or ≥ 3) messages without a reply, ≥ 3 minutes apart |
| Channel mix | % of photos, voice notes, videos, stickers, GIFs, documents, locations, forwards |
| Love bombing vs devaluation | mean % change of volume, affection, hearts, length and latency between the first and last 60 days (>40 marked devaluation, 15-40 cooling, ±15 stable, < −15 intensification) |
</details>

<details>
<summary><b>Responsiveness</b></summary>

| Metric | Definition |
|---|---|
| Latency | time between a message and the other person's reply (sender changes only, pauses > 8 h excluded) |
| Speed | % of replies within 1 and 5 minutes, over 30 minutes and 2 hours |
| Fading detector | last-3-month median vs historical median: flagged if ≥ 1.5× and robust z ≥ 2 (z = deviation / MAD×1.4826) |
| Reply dynamics | P(B writes within 3 minutes \| A wrote) and median latency of the transition |
</details>

<details>
<summary><b>Conflict and red flags</b></summary>

| Metric | Definition |
|---|---|
| Tension (0-100) | per session: conflict/blame vocabulary, replies < 15 characters or stickers, walls of text > 350 characters, repeated `?!`, caps, density, with saturating functions; ×0.4 if ≥ 30% of messages laugh |
| Tense-session threshold | the chat's 98th percentile, between 20 and 65 |
| Climate | affection (+ hearts), conflict, apologies, blame per 1000 messages; affection ÷ conflict ratio |
| Pronouns (Gottman) | share of we / I / you out of the three; "you always / you never" per 1000 words |
| Stonewalling | message > 350 characters written by the sender → reply < 15 characters, sticker/GIF or silence > 4 h; in groups only 1-to-1 dialogues |
| Apologies / blame | curated vocabularies, per 1000 messages, with real examples |
| Making up | after a tense session followed by > 4 h of silence: who writes first, after how long, and whether with an apology |
| Gaslighting, passive aggression, guilt-tripping | frequency of typical phrases per 1000 messages, with examples |
</details>

<details>
<summary><b>Vocabulary, affection and rhythms</b></summary>

| Metric | Definition |
|---|---|
| Signature words | sublinear TF-IDF (unigrams + bigrams) × exclusivity (share of the word written by that person) |
| Pet names | affectionate vocabulary + terms discovered by *lift* ≥ 2.5 next to hearts/words of love (greetings excluded) |
| Emoji fingerprint | top emoji, emoji per message, families (hearts, laughter, sadness, annoyance) over time |
| Calendar, streaks, silences | messages per day, consecutive days, longest pauses and who broke them |
| Chronotype | % of own messages by hour, time of day and weekday; peak hour |
| Reciprocity index | 100 × (1 − mean imbalance (max−min)/(max+min) over 7 reciprocity indicators); two-person chats only |
</details>

## AI Detective and local model

The **AI Detective** is an agent with 5 tools that the LLM calls on its own:

| Tool | What it does |
|---|---|
| `get_global_psychometric_dossier` | JSON dossier with every metric (computed once and cached) |
| `query_sql_database` | **read-only** SQL on the chat database, with timeout and row limit |
| `search_chat_sessions` | **BM25 (FTS5) + vector (sqlite-vec)** hybrid search fused with Reciprocal Rank Fusion, filterable by person, dates and tension |
| `analyze_specific_red_flag` | gaslighting, stonewalling, love bombing, passive aggression, guilt-tripping with examples |
| `build_persona_profile` | style profile (lengths, punctuation, words, emoji, real messages) |

The AI answers in the interface language (quoting messages in their original language). The **Persona Simulator**
uses the same profile to reply in a participant's style, or to write a group dialogue.

**The model is managed from the sidebar.** Pick one (⭐ = recommended for your RAM) and press **Download and start**:
ChatAutopsy installs the backend if missing, downloads the weights once with a progress bar, starts the
OpenAI-compatible server on `127.0.0.1`, checks that it really generates text, and restarts it automatically next
time. The server stops when you close the app.

| RAM | Recommended model (MLX, 4-bit) | Download | Ollama |
|---|---|---|---|
| 8-16 GB | Qwen3.5 4B (March 2026) | 3.1 GB | `qwen3.5:4b` |
| 16-32 GB | Qwen3.5 9B (March 2026) | 6.0 GB | `qwen3.5:9b` |
| 32-96 GB | **Qwen3.8 27B** (August 2026) | 16.1 GB | `qwen3.8:27b` |
| ≥ 96 GB | Qwen3.5 122B-A10B (MoE) | 69.6 GB | `qwen3.5:122b-a10b` |

Also available from the panel: **Qwen3.6 35B-A3B** (MoE with 3B active parameters: very fast, 20 GB) and
**Gemma 4 26B-A4B** (MoE, 15 GB). The catalogue lives in [`config.py`](chatautopsy/config.py) and is easy to update.

- **MLX** (Apple Silicon Macs): automatic, `mlx-lm` is installed if missing.
- **Ollama** (macOS/Linux): just have it installed from [ollama.com](https://ollama.com); ChatAutopsy starts it and pulls the model.
- **My endpoint**: any OpenAI-compatible server already running (LM Studio, vLLM, llama.cpp…).

## Architecture

```mermaid
flowchart LR
    A[Export<br>txt · zip · json · html] --> B[Universal parser<br>WhatsApp · Telegram]
    B --> C[Per-message features<br>emoji · punctuation · night · forwards]
    C --> D[Sessions<br>45 min of silence or 45 msgs, overlap 5]
    D --> E[(SQLite WAL<br>messages · sessions)]
    E --> F[FTS5 / BM25]
    E --> G[sqlite-vec<br>embeddings MPS/CUDA/CPU]
    D --> H[Heuristic scores<br>tension · intensity]
    E --> I[AnalyticsEngine<br>pandas, memoised, thread-safe]
    I --> J[Streamlit dashboard<br>English · Italiano]
    F & G --> K[Hybrid search RRF]
    I & K & E --> L[Tool-calling agent]
    L <--> M[Local LLM<br>MLX · Ollama · OpenAI-compatible]
```

| Module | Role |
|---|---|
| [`ingestion.py`](chatautopsy/ingestion.py) | parsers, features, sessions, tension scores, DB writing, orchestration |
| [`analytics_engine.py`](chatautopsy/analytics_engine.py) | every metric, report card, dossier for the agent |
| [`rag_engine.py`](chatautopsy/rag_engine.py) | FTS5 index, embeddings, vector and hybrid search |
| [`agent.py`](chatautopsy/agent.py) | streaming tool-calling agent (also Qwen-style text tool calls) and simulator |
| [`llm_manager.py`](chatautopsy/llm_manager.py) | model catalogue, download, start and health of the server |
| [`database.py`](chatautopsy/database.py) | schema, WAL connections, migrations, secure wipe |
| [`app.py`](chatautopsy/app.py), [`ui.py`](chatautopsy/ui.py) | dashboard and chart components |
| [`i18n.py`](chatautopsy/i18n.py), [`locales_en.py`](chatautopsy/locales_en.py) | English/Italian interface |
| [`cli.py`](chatautopsy/cli.py) | command line |
| [`config.py`](chatautopsy/config.py) | thresholds, vocabularies (IT + EN), model catalogue, paths |
| [`demo.py`](chatautopsy/demo.py) | synthetic chats (English and Italian) for demo and tests |

<details>
<summary><b>Database schema</b></summary>

- **messages**: one row per message (timestamp, sender, text, counts, emoji, media, forward flag, gap and response time).
- **sessions**: conversation blocks with participants, who started, duration, tension and intensity scores, laughter
  share and transcript `[YYYY-MM-DD HH:MM] Name: text`.
- **fts_messages / fts_sessions**: full-text indexes (unicode61, accent-insensitive).
- **session_embeddings**: `vec0` vectors (cosine distance) with NumPy fallback.
- **meta**: source, embedding model, counts.
</details>

## Performance

Measured on a Mac M3 Max (36 GB):

| Chat | Parsing | Database + scores | Semantic search (MiniLM) | First dashboard load |
|---|---|---|---|---|
| demo, 12,820 messages | 0.3 s | ~5 s | ~20 s | a few seconds |
| real, 1.34 million messages (Telegram HTML, 472 MB) | ~8 s | ~2 min | ~10 min | ~1 min (then instant) |

How: lexicon regexes compiled as a **trie** (10-20× faster than naive alternation, identical results — verified in the
tests), a single shared, memoised engine for all sections, sections computed only when opened plus background
pre-computation, WAL + `synchronous=NORMAL`, batched embeddings with periodic MPS memory release.

## Privacy and security

- **No data leaves your computer.** The only network connections are the one-off downloads of Python packages and of
  the models you choose. At runtime Hugging Face is used only from the local cache; telemetry is disabled.
- **Uploaded exports never touch the disk**: they are read in memory; only the database remains.
- **Databases** live in `data/` (git-ignored) or in `~/.chatautopsy/data`.
- **Secure wipe** (dashboard or `chatautopsy wipe`): WAL checkpoint, zero overwrite, fsync and deletion of `.db`,
  `-wal`, `-shm`. On SSD/APFS overwriting does not guarantee physical unrecoverability (copy-on-write, Time Machine
  snapshots): for maximum confidentiality use an encrypted volume.
- **The agent** has **read-only** database access (writes and multi-statement queries blocked, timeout).
- The model server listens on `127.0.0.1` only.

## FAQ and troubleshooting

<details>
<summary><b>The AI Detective says the model isn't responding</b></summary>

The model isn't running. In the **🤖 Local AI model** panel press *Download and start* (or *Start* if already
downloaded), or the button in the AI Detective section. From the terminal: `./start.sh llm setup`. If you use your own
server, enable *My endpoint* and check URL and model name. Logs are in `data/logs/llm_server.log`.
</details>

<details>
<summary><b>"Python ≥ 3.10 required"</b></summary>

macOS ships Python 3.9. Install a recent one (`brew install python@3.12` or from python.org): `start.sh` finds it by
itself, even if it isn't on the PATH.
</details>

<details>
<summary><b>The analysis is slow or the Mac slows down</b></summary>

The slow part is semantic search: use `--embeddings none` (the statistics don't need it) or the *Fast* model. Close
heavy apps (simulators, VMs): under swap everything is several times slower. `chatautopsy doctor` shows whether the GPU
(MPS) is in use.
</details>

<details>
<summary><b>"Unrecognised date format" with a Telegram HTML export</b></summary>

The export language uses a date format that isn't supported yet. Export as **JSON** instead (ISO dates, always
compatible) and open an issue with an example of the date `title` attribute (no personal content).
</details>

<details>
<summary><b>Can I analyse group chats? Chats in other languages?</b></summary>

Group chats: yes, every metric works with N participants; stonewalling counts only 1-to-1 exchanges, the reply graph
shows who answers whom, and the reciprocity index is reserved for two-person chats. Languages: the statistics work on
any language; the lexical indicators (affection, conflict, apologies…) are tuned for English and Italian.
</details>

## Disclaimer

ChatAutopsy measures **writing behaviour**, not mental states or the quality of a relationship. Lexical indicators
miss irony and context; scores are heuristic; the AI can be wrong (always check the quotes). No output is a clinical
or psychological assessment. Only analyse conversations you are part of, and respect the privacy of the other people
involved.
